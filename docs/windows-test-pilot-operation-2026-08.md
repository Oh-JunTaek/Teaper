# Windows 로컬 앱 코드 서명 전 테스트 배포 운영 기준

**적용 대상:** EunmaStudio 문제 출제 워크스페이스 로컬 앱 `0.1.0-beta.4`  
**운영 단계:** 초대 기반 소수 교사 테스트  
**배포 방식:** Windows x64 NSIS 설치 파일, 코드 서명 전

> 이 문서는 정식 공개 지침이 아닙니다. 지정된 파일럿 참여자가 본인의 Windows PC에서 로컬 모델 전용 흐름을 확인하기 위한 운영 기준입니다.

## 1. 배포 범위와 금지 사항

테스트 설치 파일은 EunmaStudio가 초대한 소수 교사에게만 제공한다. 공개 웹페이지·메신저 단체방·공개 저장소에 설치 파일을 재배포하지 않는다. 설치 파일은 웹앱의 **AI 제공자 설정 → 로컬 AI 안내**에서만 제공하며, 참여자는 파일명과 SHA-256 값을 대조한 뒤 설치한다.

| 항목 | 테스트 배포 기준 |
|---|---|
| 모델 실행 | Ollama·llama.cpp 등 교사 PC의 로컬 모델만 허용 |
| 외부 개인 API | 표시·호출·자동 전송하지 않음 |
| 자료 저장 | 자료·기출·문항·검수 이력은 해당 PC의 로컬 저장소에 보관 |
| 설치 파일 | 코드 서명 전 버전이므로 Windows 경고 가능성을 사전에 고지 |
| 파일 검증 | 웹앱·설치 안내의 SHA-256과 일치할 때만 설치 |
| 재배포 | 금지. 테스트 종료 또는 문제가 확인되면 배포 링크를 회수 |

## 2. 참여자가 수행할 설치 확인

참여자는 `README-WINDOWS-TEST.md`의 설치 확인표를 따른다. 특히 Ollama 연결, 로컬 모델 준비, 자료·기출 등록 후 재시작 보존, 문항 생성과 검수, DOCX·PDF·CSV 출력, 암호화 백업·복구를 순서대로 확인한다. 테스트 문항에는 실제 시험 출제 전 원문이나 학생 개인정보를 넣지 않는다.

| 확인 영역 | 보고할 결과 | 포함하지 말아야 할 정보 |
|---|---|---|
| 설치·실행 | 성공/실패, Windows 버전, 앱 버전 | 사용자 계정, PC 이름, 화면 전체 캡처 |
| 모델 준비 | Ollama 실행 여부, 모델명, 오류 문구 | API 키, 터미널 토큰 |
| 문항 흐름 | 자료 등록·생성·검수·출력의 성공 여부 | 실제 출제 예정 문항, 자료 본문, 학생 정보 |
| 백업·복구 | 백업 생성·복구 성공 여부 | 백업 암호, 백업 파일 자체 |

## 3. 피드백 기록 양식

파일럿 참여자는 아래 항목만 전달한다. 운영자는 문항 원문·기출 PDF·교사 자료·백업 파일·암호를 요청하거나 수집하지 않는다.

```text
[로컬 앱 테스트 피드백]
앱 버전: 0.1.0-beta.4
Windows 버전: 예) Windows 11 23H2
확인 항목: 설치 / Ollama 연결 / 문항 생성 / 검수 / DOCX / PDF / 백업 중 선택
결과: 성공 / 실패 / 개선 제안
오류 문구: 문항·자료·개인정보를 지운 뒤 짧게 복사
재현 단계: 1) ... 2) ... 3) ...
```

## 4. 문제 발생 시 회수 기준

설치 파일의 SHA-256 불일치, 의도하지 않은 외부 전송 의심, 다른 교사의 자료 노출, 백업·복구로 인한 데이터 손상, 또는 악성코드 경고가 발생하면 즉시 새 설치를 중단한다. 운영자는 웹앱의 다운로드 링크를 제거하고, 설치 파일을 받은 참여자에게 삭제·재설치 중단을 알린 뒤 원인을 분석한다. 자료 원문이나 백업 파일을 받지 않고도 재현되지 않는 경우에는 익명화된 오류 문구와 재현 단계만 요청한다.

## 5. 정식 배포 전환 조건

정식 공개로 전환하기 전에 Windows 코드 서명 인증서, 서명된 설치 파일, 검증된 업데이트 배포 경로, 설치 프로그램의 복구·업데이트 정책을 마련한다. 파일럿에서 확인된 설치·로컬 모델·문서 출력·암호화 백업 문제를 해결하고, 참여자가 실제 문항 원문 없이도 핵심 흐름을 반복 검증한 뒤 운영자가 별도로 전환 여부를 결정한다.
