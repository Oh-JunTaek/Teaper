## 1. 서비스 범위와 AI 활용 고지

교사도우미는 교사가 교육과정·출제 지침·합법적으로 이용 가능한 자료를 근거로 **문항을 생성하고 검수·승인·내보내기** 하도록 돕는 출제 보조 서비스다. 문항 결과는 생성형 AI를 활용해 작성될 수 있으며, 서비스 화면과 생성·검수 이력에는 사용한 제공자·모델·근거·검증 결과를 표시한다. 생성 결과는 시험지 완성이나 교육적 판단의 대체가 아니며, 교사가 교육과정 적합성·정답·해설·난이도·저작권·개인정보 포함 여부를 최종 검수한다. 생성형 AI 활용 사실의 사전 고지와 결과물 표시 원칙은 국내 AI 투명성 기준에 맞춰 유지한다. [1]

교사도우미는 현재 개인 교사의 문항 업무 보조를 목적으로 한다. 학생 성적 산출, 입학·진학 판단, 징계, 학생 선발처럼 개인의 권리나 교육 기회에 중대한 영향을 미칠 수 있는 결정을 AI 결과만으로 자동화하지 않는다.

## 2. 계정·작업공간·문항 보안

계정은 본인만 사용해야 하며 공유·대여·양도를 금지한다. 자료, 기출, 생성 문항, 검수 이력은 교사별 작업공간을 기준으로 분리한다. 다른 교사는 원칙적으로 해당 문항을 볼 수 없으며, 운영자는 장애·보안 사고·법적 의무 대응에 필요한 최소 범위에서만 접근한다.

출시 예정 문항은 일반 참고 자료보다 높은 보안 수준으로 취급한다. 이용자는 학교·교육청·소속기관의 평가 보안 지침이 서비스 정책보다 우선함을 이해하고 준수해야 하며, 공동 출제·기관 공유가 필요한 경우에는 기관 도입 전용 권한·승인·감사 기능이 마련되기 전까지 서비스 밖의 승인된 절차를 사용해야 한다.

| 통제 | 현재 원칙 | 출시 전 검증 항목 |
|---|---|---|
| 접근 범위 | 교사 본인 문항·자료만 조회·수정·삭제 | 서버 권한 테스트, 관리자 최소화 |
| 문항 공개 | 다른 이용자에게 자동 공유 금지 | 내보내기·링크 공유 권한 점검 |
| 운영자 접근 | 운영·보안 목적의 최소 접근 | 목적·승인·감사 기록 절차 |
| 계정 보호 | 인증 세션·역할 제한 | MFA, 비정상 접근 통지, 퇴직/이동 계정 회수 |

## 3. 참고 자료·기출문제·저작권

교사는 업로드하거나 링크·기출 정보로 등록하는 자료에 대해 이용·분석·저장할 권한을 보유해야 한다. 타인의 교재, 학교 내부 문서, 문항, 이미지, 표, PDF를 등록하는 경우 저작권·영업비밀·계약상 비밀유지의무·기관 정책을 먼저 확인해야 한다. 서비스는 공식 출처 링크와 메타데이터를 우선 제공하며, 권리 상태가 확인되지 않은 원문을 공용 카탈로그로 일괄 복제하거나 재배포하지 않는다.

기출문제는 저작물성이 인정될 수 있고, 생성형 AI와 저작물 이용은 공정이용 여부 등 개별 사정에 따른 쟁점이 있다. [2] 따라서 공식 기출은 공식 제공처 안내와 메타데이터를 기본으로 하며, 개인 교사가 직접 등록한 PDF·문항 정보는 해당 교사의 작업공간에서만 취급한다. 권리자의 삭제 요청, 침해 신고, 기관의 보안 요청이 있으면 관련 자료·생성 근거·내보내기 접근을 중지·격리·검토할 수 있다.

## 4. 개인정보·학생 정보 최소화

교사도우미는 계정 운영, 작업공간 제공, 자료·문항·검수 이력 관리, 보안 대응에 필요한 범위에서만 정보를 처리한다. 이용자는 학생 이름, 학번, 연락처, 성적, 건강·상담·가정 정보, 생체정보, 기타 민감정보를 자료·파일명·추가 지시문·AI 입력에 넣지 않아야 한다.

| 데이터 구분 | 처리 원칙 | 금지 또는 제한 |
|---|---|---|
| 계정 정보 | 로그인·보안·지원 최소 범위 | 사용자 관리 화면의 불필요한 표시 금지 |
| 문항·자료 | 개인 작업공간에서 생성·검수·내보내기 | 타인·공용 공개 기본값 금지 |
| 익명 이용 통계 | 개인 식별자·문항 원문·파일 본문을 저장하지 않는 일별 집계만 설계 | 정책 확정 전 수집 비활성 |
| 학생 정보 | 입력 금지 원칙 | 학생 성적·상담·건강·식별정보 등록 금지 |
| API 키 | 암호화 보관·화면 마스킹·로그 제외 | 원문 표시·내보내기·공유 금지 |

개인정보 처리방침에는 실제 수집 항목, 목적, 보유 기간, 처리 위탁·제3자 제공·국외이전, 이용자의 열람·정정·삭제·처리정지 권리, 문의처와 변경 이력을 명확하게 공개한다. [3]

## 5. AI 제공자·외부 전송·로컬 실행

이용자는 관리형 AI, 개인 외부 API, 로컬 AI 중 실행 방식을 선택할 수 있다. 개인 외부 API를 선택하는 경우 서비스는 전송될 문항 조건, 선택된 근거, 추가 지시문, 예상 호출 범위를 사전에 표시하고 해당 요청에 한정한 명시적 동의를 받는다. 외부 AI 제공자의 국가·보관·학습 사용 여부·약관·요금은 제공자별로 다를 수 있으므로, 출시 전 제공자별 처리 구조를 확인해 개인정보 처리방침과 전송 고지에 반영한다.

국외 사업자가 국내 서비스가 보유한 개인정보를 조회하는 경우에도 국외이전에 해당할 수 있으며, 적법한 이전 근거, 처리방침 공개, 안전조치, 고충처리·분쟁 해결 조치가 요구될 수 있다. [4] 학생 개인정보 또는 출시 예정 시험 원문은 외부 AI로 보내지 않는 것을 기본 원칙으로 한다.

로컬 AI는 교사 PC의 Ollama 등에서 실행되며 자료와 문항 원문을 PC 밖으로 보내지 않는 local-only 모드를 지향한다. 다만 로컬 모델의 성능·출력 품질·모델 라이선스·PC 보안은 교사 환경에 따라 달라질 수 있으므로, 로컬 모델도 동일하게 근거·정답·해설 검수를 거쳐야 한다.

## 6. 보관·삭제·백업·내보내기

파일럿 단계에서는 다음 임시 기준을 적용하고, 정식 공개 전 실제 데이터베이스·S3·백업·로그 구조에 맞춰 보유기간과 파기 방식을 확정한다.

| 대상 | 이용자 조치 | 운영 기준 | 정식 공개 전 확정 사항 |
|---|---|---|---|
| 참고 자료·기출 PDF | 삭제 가능 | 삭제 뒤 신규 생성 근거에서 제외 | 원본·백업 완전 파기 시점 |
| 생성 문항·검수 이력 | 삭제·내보내기 요청 경로 제공 | 문항 근거 스냅샷은 검수 추적에 필요 | 보존기간·법적 보존 예외 |
| 개인 API 키 | 설정 변경·연결 해제 | 암호화·마스킹·로그 제외 | 키 교체·복구·파기 절차 |
| 보안·감사 기록 | 직접 수정 불가 | 최소 범위로 보안 조사에 사용 | 보존기간·접근 승인·파기 절차 |
| 익명 통계 | 수집 전 고지·기본 비활성 | 개인 식별 불가한 집계만 허용 | 목적·주기·보유기간·거부 방식 |

삭제 요청과 백업 복원 가능성, 법령·분쟁·침해조사에 따른 보존 예외를 이용자가 이해할 수 있게 고지한다. 내보낸 파일은 이용자 기기 또는 지정 저장소에서의 관리 책임이 이용자에게 있음을 안내한다.

## 7. 정보보안·사고 대응

EunmaStudio는 접근권한 최소화, 전송·저장 암호화, API 키 암호화, 비밀정보 로그 제외, 의존성·취약점 점검, 백업·복구 훈련을 운영 기준으로 둔다. 개인정보 유출 또는 보안 사고가 의심되면 신규 접근·전송을 격리하고, 증거와 로그를 보존하며, 영향 범위·통지·신고 요건을 판단한다. 일정 요건의 개인정보 유출은 72시간 내 신고 대상이 될 수 있다. [5]

| 사고 단계 | 담당 행동 |
|---|---|
| 탐지·접수 | 사고 ID 발급, 영향 서비스·데이터·시간 기록, 비밀정보 노출 여부 판단 |
| 격리 | 관련 계정·키·외부 전송·공유 링크 차단, 필요한 경우 서비스 기능 임시 중지 |
| 보존·분석 | 로그·스냅샷·관련 설정을 원형 보존하고 원인·범위 분석 |
| 통지·신고 | 법정 통지·신고·기관 통보 요건과 기한 판단, 이용자 피해 최소화 안내 |
| 복구·재발방지 | 키 교체, 권한 재검토, 취약점 수정, 사후 보고와 정책·훈련 갱신 |

## 8. 서비스 품질·지원·변경 관리

서비스는 파일럿 단계이므로 무중단 서비스 수준이나 특정 모델의 품질을 보장하지 않는다. 장애·점검·AI 제공자 한도 초과·로컬 PC 성능 부족은 생성 지연 또는 실패를 초래할 수 있다. 서비스는 원인을 가능한 범위에서 안내하고, 이용자는 수동 검수 또는 다른 제공자를 명시적으로 선택할 수 있다.

기능·정책·데이터 처리 방식이 변경되면 `CHANGELOG.md`와 정책 변경 이력에 목적·영향·시행일을 기록한다. 문항·자료·개인정보에 중대한 영향을 주는 변경은 서비스 내 공지와 합리적 사전 고지를 원칙으로 한다. 문의·불만·침해 신고·권리 요청은 정식 공개 전 확정할 EunmaStudio 문의처와 접수 절차를 통해 처리한다.

## 9. 금지 행위와 조치

이용자는 다음 행위를 해서는 안 된다: 학생 개인정보·민감정보의 등록, 권한 없는 저작물·영업비밀 업로드, 계정 공유, 다른 이용자 자료 접근 시도, 시험문항 보안 우회, API 키 공유, 서비스 취약점 악용, 생성 결과를 검수 없이 자동 배포하는 행위. EunmaStudio는 합리적 근거가 있는 경우 관련 자료의 격리, 생성·내보내기 제한, 계정 이용 제한, 권리자·기관 문의 대응 등 필요한 조치를 할 수 있다. 긴급 조치 뒤에는 가능한 범위에서 이용자에게 사유·이의 제기 경로를 안내한다.

## 10. 기관 도입·유료화 전 추가 요건

학교·교육청·학원 등 기관 도입 또는 유료화 전에는 개인 교사 파일럿 정책만으로 충분하지 않다. 기관별 계약, 역할 기반 조직 관리, 공동 출제 승인, 관리자 감사 로그, DPA/처리위탁·국외이전 계약, SLA, 백업·재해복구, 데이터 이전·반환·파기, 고객지원 시간, 가격·결제·환불·분쟁처리, 사업자·통신판매 정보 고지를 별도로 확정한다. 전자상거래 거래를 개시하는 경우 사업자 신원·가격·공급·청약철회/환불·불만·분쟁 처리·약관 등의 거래조건 고지 기준을 확인해야 한다. [6]
