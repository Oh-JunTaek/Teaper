# iOS Version 1.0 출시 준비 체크리스트

**서비스:** EunmaStudio 교사도우미  
**대상 번들:** `com.eunmastudio.teacherworkspace`  
**현재 소스 버전:** `0.1.0`  
**Version 1.0 의미:** 기능을 더 넓히는 선언이 아니라, iOS에서 약속한 local-only 쪽지시험 업무를 실제 iPhone에서 안정적으로 검증해 TestFlight와 App Store 심사에 제출 가능한 **최초 공개 후보**를 뜻합니다.

> **현재 판정: Version 1.0의 코드 기반은 준비됐지만 App Store 제출은 아직 시작하면 안 됩니다.** `DEVELOPMENT_TEAM` 미설정, macOS/Xcode 빌드 미실행, 실제 iPhone 모델·출력·안정성 검증 미완료, 공개 개인정보 처리방침·지원 URL 미확정이 제출 차단 요건입니다.

## 1. Version 1.0 범위 고정안

Version 1.0은 ‘모든 웹 기능을 iPhone으로 옮긴 앱’이 아닙니다. **교사가 iPhone 안에서 짧은 쪽지시험을 만들고, 문항별로 검수·승인하고, 학생용 문제만 공유하는 local-only 도구**로 범위를 고정하는 것이 현실적입니다. 자료·일반 문항·메모·일정·AI 채팅·기관 동기화는 Version 1.0의 스토어 설명·스크린샷·심사 메모에 포함하지 않습니다.

| 영역 | Version 1.0 포함 | 현 소스 상태 | 심사·실기기 전제 |
|---|---|---|---|
| 오늘의 작업 | 검수 대기·승인 수, local-only 안내 | 구현됨 | iPhone 작은 화면·Dynamic Type 확인 |
| 쪽지시험 생성 | 중등/고등, 객관식·주관식·O/X, 낮음·보통·높음, 1~5문항 | 구현됨 | E2B/E4B 실제 생성·발열·메모리·중단 복구 확인 |
| 문항별 검수 | 정답·해설 확인 후 승인·수정 필요·반려 | 구현됨 | 1·3·5문항, 긴 보기·화학식 표기 확인 |
| 배점 부여 | 정답·해설 뒤 `배점 부여`, 0~100점·소수 첫째 자리, 승인 시 저장, 비우면 미표기 | 코드 반영됨 | iPhone에서 승인·수정·빈 값·PDF 반영 확인 |
| 승인 문항 | 승인 문항 보관·학생용 텍스트/PDF 공유 | 구현됨 | Files·AirPrint·메신저별 공유와 다쪽 PDF 확인 |
| 워터마크 | 교사 기본 학생용 PDF의 오른쪽 아래 여백, 플러스 제거 | 코드 기반 있음 | 실제 서명 빌드의 기본/플러스 표기 확인 |
| 자료·일반 문항·메모·일정·AI 채팅 | **포함하지 않음** | 미구현 또는 준비 수준 | Version 1.1 이후 별도 범위 승인 |
| 계정·웹 동기화·개인 API | **포함하지 않음** | 미구현 | 사용자 자료 자동 업로드 금지 원칙 유지 |

이 범위에서는 자료, 문항, 대화 원문, 모델 파일을 서버나 다른 기기로 자동 전송하지 않습니다. 앱은 iOS Application Support 저장소를 쓰고 파일 보호·백업 제외 처리를 시도하지만, 이 설계만으로 모든 기기 분실·공유 후 유출 위험이 사라지는 것은 아닙니다. Version 1.0의 서비스 설명에는 ‘교사가 공유한 파일은 선택한 수신 앱의 정책을 따른다’는 경계를 분명히 넣어야 합니다.

## 2. 제출 전 차단 요건

Apple은 심사 제출본이 완성된 앱, 작동하는 URL, 정확한 메타데이터여야 하며 실제 기기에서 충돌·기능 오류를 시험하도록 요구합니다. 베타·시험용 앱은 App Store가 아니라 TestFlight로 배포해야 합니다.[1] 또한 iOS 앱에는 개인정보 처리방침 URL이 필요하고, App Store Connect의 개인정보 답변은 앱과 포함한 제3자 코드의 실제 데이터 처리 관행을 포괄·정확하게 반영해야 합니다.[2]

| 우선순위 | 차단 요건 | 완료 기준 | 현재 상태 |
|---|---|---|---|
| P0 | Apple 서명·빌드 | Apple Developer Program 팀 설정, Release Archive, 실제 기기 설치 | **미완료** — `DEVELOPMENT_TEAM` 비어 있음 |
| P0 | Xcode 품질 검증 | Xcode build/test, iPhone 실기기 크래시·경고 0건, LiteRT-LM 패키지 해석 | **미완료** — Linux에서는 Xcode 실행 불가 |
| P0 | 모델 실사용 | E2B 기본·E4B 선택의 다운로드/가져오기, 저장 공간 부족, 오프라인 생성, 종료·재실행, 발열·배터리 기록 | **미완료** |
| P0 | 학생용 출력 | 승인 문항만, 정답·해설·난이도·검수·생성 정보 미노출, 화학식 아래·위첨자, 배점 표기/미표기, 다쪽 PDF | **미완료** — 코드 반영, iPhone 실출력 미검증 |
| P0 | 공개 운영 고지 | 개인정보 처리방침 URL, 지원 URL·문의 이메일, 삭제·침해 신고 안내, 이용약관 | **미완료** |
| P1 | App Store Connect | 실제 기능을 반영한 앱 이름·부제·설명·키워드·스크린샷·연령 등급·개인정보 답변·심사 메모 | **미완료** |
| P1 | TestFlight | 내부 테스트 → 외부 TestFlight, 비보상 테스터, 회귀 목록·오류 회수 절차 | **미완료** |
| P1 | 모델·자료 권리 | LiteRT-LM·E2B/E4B 배포·다운로드 방식과 모델 카드·라이선스, 외부 자료 링크의 이용 조건 검토 | **미완료** |
| P1 | 접근성·지원 | Korean Dynamic Type, VoiceOver, 대비, 오류 문구, 네트워크·저장공간 부족 안내 | **미완료** |

## 3. TestFlight까지의 권장 순서

| 단계 | 수행 내용 | 통과 증적 | 실패 시 조치 |
|---|---|---|---|
| 1. 기술 빌드 | macOS/Xcode에서 패키지 해결, Debug·Release build, XCTest | 빌드 로그·테스트 결과·Archive | 컴파일 오류, 서명 오류, 라이브러리 호환 오류부터 해결 |
| 2. 내부 iPhone QA | 최소 2개 iPhone/iOS 조합에서 E2B, 가능하면 E4B 검증 | 기기/OS/저장공간/처리시간/발열 기록 | 모델 실행·메모리·화면 종료 문제 수정 |
| 3. 출력·보안 QA | 1·3·5문항, 여러 페이지, 배점/미표기, 워터마크, 학생용 민감 정보 미노출, 앱 잠금·재시작·공유 | PDF·텍스트 표본, 체크리스트, 결함 목록 | P0 항목은 TestFlight 전 수정 |
| 4. TestFlight 내부 배포 | 운영자·개발자·소수 교사에게 내부 배포 | 테스트 안내, 피드백·크래시 기록 | 기능·설명·정책 불일치 정정 |
| 5. 외부 TestFlight | 스토어 공개 전 소수 교사 제한 검증 | 심사 통과, 교사 피드백, 알려진 문제 목록 | 심각 결함·정책 이슈는 빌드 회수 |
| 6. App Store 제출 | 최종 Release Archive와 실제 메타데이터 제출 | 심사 메모·지원 URL·정확한 개인정보 답변 | TestFlight에서 재검증 후 재제출 |

> Version 1.0의 App Store 스크린샷은 로그인 화면이나 임시 안내가 아니라, 실제로 사용할 수 있는 ‘쪽지시험 생성 → 문항별 검수 → 학생용 PDF 공유’ 흐름을 보여야 합니다. 앱이 하지 않는 자료 관리·일반 문항·AI 채팅·기관 동기화를 설명에 넣으면 안 됩니다.[1]

## 4. Version 1.0 테스트 카드

아래는 실제 테스트 시 결과를 `통과`, `수정 필요`, `재현 불가` 중 하나로 기록할 최소 항목입니다.

| 기능 | 확인 절차 | 기대 결과 |
|---|---|---|
| 최초 실행 | 앱 설치 → 모델 관리 열기 → 권한/저장공간 안내 확인 | 안내가 한국어로 보이고, 실패해도 앱이 종료되지 않음 |
| 모델 | E2B 준비 → 오프라인 쪽지시험 1문항 생성 → 앱 종료/재시작 | 저장한 세트가 남고 생성 결과가 표시됨 |
| 높은 난이도 | 고등·높음·객관식 선택 → 조건 적용 주제 생성 | 단순 정의 암기가 아닌 짧은 조건 적용·관계 해석·계산·오개념 판별 중 하나를 포함 |
| 과학 표기 | `H2O`, `SO4^2-`, `CO3^2-`, `1s2`가 들어간 문항 | 화면·텍스트·PDF에서 `H₂O`, `SO₄²⁻`, `CO₃²⁻`, `1s²`로 보임 |
| 검수·배점 | 정답·해설 확인 → `배점 부여`에 `3.5` → 승인 → 재열기 | 상태와 배점이 함께 저장되며, 비우고 저장하면 미표기 |
| 학생용 PDF | 승인 1개/여러 개, 배점 표시 켬/끔, 기본 플랜 | 승인 문항만 보이고 금지 정보는 없으며, 켠 경우만 `［3.5점］`, 기본 플랜 워터마크는 하단 여백 |
| 공유 | Files·AirPrint·메신저 중 가능한 대상 선택 | 공유 시작 전 내용이 맞고, 취소해도 원본 세트가 손상되지 않음 |
| 접근성 | 글자 크기 확대, VoiceOver, 가로/세로 회전 | 버튼 이름·입력·검수 상태를 읽을 수 있고 화면이 겹치지 않음 |
| 예외 | 저장공간 부족, 모델 없음, 네트워크 끊김, 빈 배점 | 이해 가능한 안내가 나오며 강제 종료되지 않음 |

## 5. Version 1.0 운영 문구 초안

스토어 설명과 앱 안의 고지는 다음 원칙을 지킵니다. ‘AI가 시험문제를 완성한다’는 표현 대신, **교사가 최종 검수하는 출제 보조 도구**라고 고지합니다. 학생용 출력에는 승인한 문항만 들어가며, 정답·해설 등 교사용 정보는 제외됩니다. 온디바이스 처리 범위와 모델 준비 방식은 실제 빌드에서 검증한 내용만 설명합니다. E2B/E4B의 속도·발열·정확성은 기기마다 다를 수 있으므로 보장 문구를 쓰지 않습니다.

개인정보 처리방침에는 앱이 local-only로 설계됐더라도 앱 저장소, 공유 기능, 충돌 보고·분석 SDK, 모델 다운로드 방식, 외부 링크를 포함한 실제 데이터 흐름을 빠짐없이 반영해야 합니다. iOS·웹·Android의 데이터 처리 방식이 다르면, App Store Connect 답변은 iOS 앱에서 실제 포함되는 코드와 기능을 기준으로 신중히 구분해야 합니다.[2]
