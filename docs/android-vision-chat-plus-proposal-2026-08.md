# Android 온디바이스 이미지 대화 · 교사 플러스 제안

**상태:** 기술 검증 완료, 구현 승인 전 설계  
**대상 모델:** Gemma 4 E2B 기본 / Gemma 4 E4B 고성능 선택  
**처리 원칙:** 이미지와 응답은 기기 안에서만 처리하고 외부 전송을 하지 않음

## 결론

**이미지 질의응답은 교사 플러스의 유효한 후보입니다.** 교사가 화학 구조식, 그래프, 실험 장면, 교과서 일부를 사진으로 첨부해 ‘이 그림의 핵심 개념은 무엇인가’, ‘표현 오류가 있는가’를 기기 안에서 질의하는 기능은 텍스트 채팅보다 명확한 추가 가치를 만듭니다.

다만 이 기능은 단순히 버튼을 잠그는 방식으로 출시하면 안 됩니다. 현재 Android 앱은 독립형 로컬 앱으로 웹 계정·플랜 권한을 조회하지 않으므로, 실제 유료 권한은 향후 **교사 플러스 라이선스/암호화 작업 꾸러미** 설계와 연결해야 합니다. 그 전 파일럿에서는 ‘교사 플러스 미리보기’로 화면·성능·보안만 검증하고, 정식 과금이나 서버 계정 조회는 연결하지 않는 것이 맞습니다.

| 항목 | 권장 결정 |
| --- | --- |
| 플랜 위치 | 교사 플러스의 차별 기능으로 배치 |
| 기본 플랜 | 텍스트 온디바이스 채팅은 계속 제공, 이미지 첨부는 기능 소개·미리보기 안내 |
| 플러스 | 이미지 1장 + 질문의 온디바이스 질의응답, 이미지별 명시적 처리·삭제 안내 |
| 처리 위치 | Android 앱 전용 LiteRT-LM, 외부 API·S3·서버 전송 없음 |
| E2B | 기본 지원, 이미지 1장·권장 해상도 제한 |
| E4B | 고성능 기기 권장, GPU 우선·CPU 폴백, 발열·메모리 안내 |
| 정식 권한 | 웹 계정 자동 조회가 아니라 교사 동의 기반의 별도 라이선스/암호화 권한 꾸러미가 준비된 뒤 연결 |

## 기술 확인

LiteRT-LM Kotlin API는 호환 모델에서 `EngineConfig`의 `visionBackend`와 `Contents.of(Content.ImageFile(...), Content.Text(...))`를 제공한다. Gemma 4 문서는 E2B·E4B를 모바일·에지 모델로 설명하고 모든 Gemma 4 모델의 이미지 입력을 명시한다. 현재 Android 실행기에도 이미지 파일과 텍스트를 보내는 `inspectImage` 경로가 존재하고, CPU/GPU 초기화 시 `visionBackend`를 이미 설정한다.[1][2]

현재 `inspectImage`는 스트리밍 응답 경로이므로, 앞선 텍스트 채팅·쪽지시험의 안정화 원칙과 다르게 처리된다. 이미지 채팅 MVP는 이를 재사용하지 않고 **완료형 동기 호출**로 바꿔야 한다. 한 장의 이미지와 한 질문을 별도 Conversation으로 처리하고, 응답을 저장한 뒤 Conversation을 즉시 닫아야 한다.

## 보안·저장 경계

| 단계 | 처리 | 보안 통제 |
| --- | --- | --- |
| 1. 선택 | Android 시스템 문서 선택기로 JPEG/PNG 한 장을 선택 | 사진 앨범 전체 권한을 요구하지 않고 선택한 URI만 읽음 |
| 2. 준비 | 앱 전용 캐시에 축소 사본을 생성 | 원본 경로·EXIF 위치 정보는 대화 저장소에 기록하지 않음 |
| 3. 확인 | ‘이 이미지는 기기 안에서만 처리됩니다. 시험 예정 원문·학생 식별정보를 확인하세요’ 고지를 교사가 승인 | 외부 전송 없음, 전송 동의가 아니라 기기 내 처리 인지 확인 |
| 4. 생성 | E2B/E4B Vision Backend + 별도 Conversation으로 완료형 응답 | GPU 실패 시 CPU 폴백, 빈 응답·오류는 저장하지 않음 |
| 5. 정리 | 응답 확정 또는 오류 직후 임시 이미지 삭제 | 앱 종료·취소·예외 흐름에서도 `finally`에서 삭제 |
| 6. 기록 | 대화에는 ‘이미지 1장에 관한 질문’과 텍스트 응답만 저장 | 이미지 바이트·미리보기·경로는 기본 미저장 |

정식 제품에서 교사가 이미지를 대화와 함께 보관해야 한다면, 그 기능은 별도 동의와 암호화 저장·삭제·내보내기 정책을 가진 후속 범위로 분리해야 합니다.

## 성능 안전장치

E2B/E4B의 모바일 메모리 요구량에는 대화 문맥과 이미지 전처리 메모리가 별도이므로, 이미지 기능은 텍스트 채팅보다 보수적으로 제한해야 합니다.[2]

1. 한 요청에 한 장만 허용하고, JPEG/PNG·최대 4MB·긴 변 1,600px로 시작합니다.
2. 이미지 모드에서는 최근 대화 원문을 주입하지 않고, 현재 질문과 짧은 교사 지시만 사용합니다.
3. E2B를 기본값으로 표시합니다. E4B에는 ‘고성능 기기 권장 · 발열과 대기 시간이 늘 수 있음’을 표시합니다.
4. GPU 선호 설정이면 Vision Backend도 GPU를 먼저 시도하고, 실패하면 조용히 CPU로 전환하되 상태 문구에는 실제 모드를 표시합니다.
5. 생성 중에는 재선택·중복 전송을 비활성화하고, 앱 잠금 재진입·Activity 종료 시 실행을 취소하고 캐시를 지웁니다.

## 화면 흐름

1. 채팅 작성 바 왼쪽에 작은 **이미지** 버튼을 추가합니다.
2. 교사 기본 사용자는 ‘이미지 대화는 교사 플러스 기능입니다’라는 짧은 소개와 기기 내 처리 원칙·지원 모델 안내를 봅니다.
3. 플러스 권한이 확인되면 시스템 선택기를 열고, 이미지를 고른 뒤 질문을 입력합니다.
4. 모델은 완료된 답변만 말풍선에 기록합니다. 중간 토큰은 표시하지 않습니다.
5. 답변 하단에는 ‘이미지 원본은 처리 후 이 기기에서 삭제됨’ 상태만 표시합니다.

## 구현 순서

| 순서 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 완료형 `inspectImageFinal` 실행기·임시 파일 삭제 정책 | 단위 테스트에서 성공·실패·취소 모두 삭제 확인 |
| 2 | 시스템 문서 선택기, 축소 사본, 이미지 1장 UI | 사진 전체 권한 없이 JPEG/PNG 선택 확인 |
| 3 | 교사 플러스 기능 안내·파일럿 권한 플래그 | 기본 플랜에는 안내, 플러스에는 선택 흐름 |
| 4 | E2B/E4B S25+ 실기기 테스트 | 응답 완료·앱 종료 미발생·캐시 삭제·GPU/CPU 상태 확인 |
| 5 | 정식 라이선스/암호화 권한 꾸러미 연결 | 결제·계정·로컬 개인정보 경계가 확정된 뒤에만 진행 |

## 권고

**‘교사 플러스 온디바이스 이미지 대화’로 구현을 진행할 수 있습니다.** 그러나 정식 유료 잠금은 웹 플랜을 Android에 무단 동기화하는 방식이 아니라, 사용자가 선택적으로 가져오는 암호화된 권한 꾸러미 또는 별도 라이선스 활성화가 준비된 뒤에 붙여야 합니다. 그 전에는 플러스 미리보기/파일럿 권한으로 안정성과 가치부터 검증하는 것이 안전합니다.
