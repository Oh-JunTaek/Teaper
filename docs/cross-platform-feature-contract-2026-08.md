# EunmaStudio 3플랫폼 기능 동등성·변경 관리 계약

## 목적

웹앱, Windows 로컬 앱, Android 앱은 교사가 자료를 준비하고 문항을 생성·검수·관리하는 **동일한 서비스 경험**을 지향한다. 이후 기능 요청은 구현 전에 공통 기능인지, 기기 전용 기능인지, 보안 검토가 필요한 동기화 기능인지를 구분한다. 변경을 한 플랫폼에만 적용하는 경우에는 이유와 후속 적용 계획을 이 문서 또는 변경 기록에 남긴다.

| 구분 | 기본 처리 원칙 | 적용 예시 |
|---|---|---|
| 공통 업무 기능 | 웹·Windows·Android에 동일한 사용자 의미와 데이터 계약을 먼저 정의한다. | 자료 준비, 문항 생성, 검수, 문서 출력, 대화 제목, 즐겨찾기, 삭제 |
| 모바일 전용 기능 | Android에만 적용하고 예외·사유를 기록한다. | 온디바이스 Gemma 실행, 모델 다운로드, 생체 잠금, Android 공유 시트 |
| Windows 전용 기능 | 로컬 PC 환경에만 적용하고 예외·사유를 기록한다. | Ollama·llama.cpp 연결, OS 보안 저장소, 로컬 인쇄 대화상자 |
| 웹 전용 기능 | 웹 서비스에서만 가능한 기능으로 표시한다. | 계정 기반 관리, 기관 운영 도구, 서버 측 공식 카탈로그 |
| 동기화 기능 | 개인·문항 보안 영향 평가와 명시 동의 설계가 끝난 뒤에만 구현한다. | 기기간 대화·자료·문항 이력 동기화 |

## 대화 기록 공통 계약

대화 스레드는 제목, 제목의 생성 방식, 즐겨찾기 여부·지정 시각, 최근 갱신 시각, 메시지 목록, 삭제 상태를 공통 의미로 가진다. 제목은 최근 의미 있는 사용자 질문에서 자동으로 추천하되, 교사가 직접 제목을 수정하면 이후 자동 변경하지 않는다. 즐겨찾기는 최근에 즐겨찾기한 스레드부터 목록 상단에 표시한다. 최근 시간은 현재 시각과 스레드 갱신 시각의 차이로 표시한다.

| 필드 | 의미 | Android alpha.19 | 웹 | Windows |
|---|---|---|---|---|
| `title` | 교사가 식별할 대화 제목 | 구현 | 다음 공통 UI 반영 대상 | 다음 공통 UI 반영 대상 |
| `titleSource` | 자동 추천 또는 교사 수정 여부 | `isTitleEdited`로 구현 | 설계 반영 대상 | 설계 반영 대상 |
| `favoriteAt` | 즐겨찾기 지정 시각 | 구현 | 설계 반영 대상 | 설계 반영 대상 |
| `updatedAt` | 최근 메시지·관리 변경 시각 | 구현 | 기존 이력 모델과 매핑 검토 | 기존 SQLite 모델과 매핑 검토 |
| 메시지 원문 | 대화 내용 | 앱 전용 저장 | 사용자 웹 작업공간 | PC 전용 SQLite |

## 동기화의 보안 경계

현재 세 플랫폼의 대화 원문은 **자동으로 동기화하지 않는다.** Android는 앱 전용 저장소, Windows는 local-only SQLite, 웹은 계정별 서버 작업공간을 사용한다. 이 분리는 출시 예정 문항과 수업 자료가 교사 의도 없이 외부로 이동하지 않게 하기 위한 기본 경계다.

대화 기록을 세 플랫폼에서 실제로 동기화하려면, 기본 비활성 상태의 명시 동의, 암호화 키 소유·복구 정책, 기기 추가 확인, 동기화 범위 선택, 충돌 해결, 원격 삭제, 보존 기간, 보안 사고 대응을 먼저 확정해야 한다. 따라서 이 기능은 **‘동기화 켜기’에 명시적으로 동의한 교사만 선택할 수 있는 암호화 동기화**로 별도 설계·승인 후 구현한다. 동의 전에는 제목·즐겨찾기·메시지 원문 어느 것도 다른 플랫폼에 전송하지 않는다.

## 변경 절차

1. 새 기능 요청마다 공통·모바일 전용·Windows 전용·웹 전용·동기화 필요 여부를 분류한다.
2. 공통 기능이면 공통 필드·사용자 용어·삭제·내보내기 규칙을 먼저 정하고 세 플랫폼 작업 목록에 반영한다.
3. 단일 플랫폼 구현이 먼저 필요하면 기능 플래그, 제한 사항, 다른 플랫폼의 후속 적용 기준을 남긴다.
4. 대화·자료·문항 원문이 기기를 벗어나는 기능은 별도 보안 검토와 교사 명시 동의 전에는 구현하지 않는다.
