# 출시 준비 점검 보고서

**서비스:** EunmaStudio 문제 출제 워크스페이스  
**점검일:** 2026-08-27  
**판정 성격:** 이 문서는 코드·설정·자동 검증·공식 스토어 기준을 대조한 **운영 준비 점검**입니다. 개인정보, 저작권, 전자상거래 또는 청소년 관련 법률의 적법성 의견이나 법률 자문이 아닙니다. 정식 공개 전에는 담당 법무·개인정보 책임자 또는 외부 전문가의 검토가 필요합니다.

> **종합 판정: 정식 공개 출시는 보류합니다.** 웹은 필수 운영 고지와 제한 파일럿 통제를 완료한 뒤에만 소수 초대자 대상의 제한 파일럿을 검토할 수 있습니다. Windows와 Android는 실제 설치·기기 검증 전의 내부/제한 테스트 단계이며, iOS는 App Store 제출 준비 이전의 구현 기반 단계입니다.

## 점검 범위와 이번 즉시 조치

이번 점검은 웹 서버·운영 의존성, Windows Electron의 운영 의존성, Android의 Gradle·Manifest 정적 선언, iOS Xcode 프로젝트 설정 및 학생용 출력 보안 경계를 대상으로 했습니다. 자동 검증이 실제 기기·실계정·스토어 심사를 대체하지 않는다는 점을 전제로 합니다.

| 구분 | 이번에 확인·조치한 내용 | 증적 |
|---|---|---|
| 웹 운영 의존성 | AWS SDK, tRPC, Express, Drizzle, Axios, nanoid, Recharts, Streamdown을 호환 가능한 보안 버전으로 업데이트했습니다. | `pnpm audit --prod --audit-level=high`: `No known vulnerabilities found` |
| 웹 서버 보호 | 프로덕션에 `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`를 적용하고, API 응답은 `no-store`로 설정했습니다. | `server/_core/securityHeaders.ts`, 자동 테스트 4건 |
| 교차 사이트 요청 | SameSite=None 세션 쿠키가 쓰이는 API 상태 변경 요청은 동일 출처에서만 허용하도록 보호했습니다. Origin이 없는 플랫폼 예약 작업은 별도 예약 작업 인증을 계속 거칩니다. | `server/_core/securityHeaders.ts`, 자동 테스트 4건 |
| 자료 원본 보호 | `/manus-storage/`가 인증되지 않은 임의 키에 임시 다운로드 URL을 발급하지 않도록 교사별 자료·기출 키와 파일럿 세션을 함께 확인합니다. 공개 허용은 배포된 Windows 테스트 설치 파일의 명시적 키 하나로 한정했습니다. | `server/_core/storageProxy.ts`, 자동 테스트 2건 |
| 오류 노출 | 공식 자료 변경 점검 실패 시 내부 오류 원문을 HTTP 응답에 넣지 않고 서버 로그에만 남기도록 변경했습니다. | `server/scheduled/officialSourceCheck.ts` |
| Windows 운영 의존성 | Electron local-only 앱의 운영 의존성 감사를 다시 수행했습니다. | `desktop/pnpm audit --prod --audit-level=high`: `No known vulnerabilities found` |

Android의 API 36 설정은 2026-08-31부터 신규·업데이트 앱에 적용되는 Google Play target API 요구와 일치합니다.[3] 다만 Data safety 양식과 공개 개인정보 처리방침은 데이터 미수집 앱에도 요구될 수 있으며, 코드 선언만으로 제출 요건을 충족했다고 볼 수 없습니다.[2] Apple 역시 실제 기기에서의 안정성, 정확한 메타데이터·지원 연락처·개인정보 고지 및 TestFlight 기반 베타 검증을 요구하므로, iOS 프로젝트의 현재 설정만으로는 심사 제출 준비 상태가 아닙니다.[4]

## 개인정보·AI·자료 권리 운영 게이트

PIPC의 생성형 AI 개인정보 처리 안내는 목적 설정부터 개발, 적용·관리까지 개인정보 보호와 정보주체 권리, 거버넌스를 함께 검토하도록 안내합니다.[1] 이 서비스의 웹·개인 API·local-only 실행 경계는 그 방향에 맞춰 구현되어 있으나, 실제 공개 전에 아래 운영 문서를 공개 URL로 제공하고 책임자를 지정해야 합니다.

| 게이트 | 정식 공개 전 필요한 산출물 또는 결정 | 현 상태 |
|---|---|---|
| 개인정보 처리 | 처리 목적·항목·보유 기간·파기·국외 이전·수탁·권리 행사·문의처가 실제 운영 조건과 일치하는 개인정보 처리방침 | **미완료: 초안만 존재, 공개 URL·담당자 확정 필요** |
| 이용·지원 | 이용약관, 허용 사용, 계정/파일럿 접근 회수, 장애·침해 신고·삭제 요청의 응답 책임자와 지원 URL | **미완료** |
| 외부 AI 전송 | 개인 API 선택 시 전송 대상·수신자·국외 이전·저장·보유 조건, 동의 기록 및 철회/대안의 법무 검토 | **미완료: UI 동의는 구현, 법무 검토·정책 확정 필요** |
| 저작권·자료 | 교사 업로드 교재·기출·이미지의 권리 확인 책임, AI 입력·보관·출력·공유 제한, 권리자 요청 처리 절차 | **미완료: 정책 초안과 공식 링크 안내는 있음, 전문가 검토 필요** |
| 학생용 출력 | 승인 문항만 전달하고 정답·해설·개념 메모·난이도·검수/생성 정보를 제외하는 실제 생성물 표본 검수 | **자동 회귀 검증 있음, 실출력 수동 표본 검수 필요** |
| 청소년·교육 운영 | 서비스 대상, 교사 책임, 학생 개인정보 입력 금지, 민감 성적·평가자료 처리 금지 또는 보호 대책 | **정책 문구 재검토 필요** |

한국저작권위원회는 권리·분쟁 상담 경로를 제공하지만, 특정 기출·교재·이미지의 AI 처리와 재배포 적법성을 이 보고서가 단정하지는 않습니다.[5] 정식 공개 범위의 자료 정책은 권리자 정책, 계약 조건 및 전문 검토에 따라 확정해야 합니다.

## 보안·운영의 잔여 위험

이번 조치는 코드상 즉시 보완 가능한 고위험 항목을 줄였지만, 서비스 운영 통제까지 자동으로 제공하지는 않습니다. 특히 현재 웹 서버에는 애플리케이션 내부 속도 제한이나 WAF가 없으므로, Autoscale 배포의 엣지/게이트웨이에서 로그인·초대 코드·비용이 드는 생성 요청에 대한 요청 속도 제한, 봇 탐지, 경보 기준을 설정하고 운영자가 점검해야 합니다. 또한 웹의 공개 URL은 상시 정식 서비스가 아니라 현재 파일럿 접근 경계로만 운용해야 합니다.

| 항목 | 현 상태 | 출시 전 후속 조치 |
|---|---|---|
| 취약점 지속 감시 | 이번 운영 감사 high 이상 0건 | SBOM 생성, 오픈소스 라이선스 목록, 월 1회 이상 감사·긴급 패치 책임자·기록 절차 수립 |
| 비밀·접근 회수 | 환경 변수 사용, 초대 코드/게스트 세션 만료 구현 | 파일럿 종료·유출 의심 시 초대 코드와 게스트 비밀번호 즉시 교체, 세션 무효화, 참여자별 접근 회수 절차 리허설 |
| 로그·오류 | 예약 작업 외부 오류 원문 차단 | 운영 로그의 자료 원문·API 키·개인정보 비포함 여부와 보존 기간을 실제 배포 환경에서 샘플 점검 |
| 복구·롤백 | 코드 체크포인트와 Windows 암호화 백업 기능 존재 | 웹 DB·객체 저장소 복구 범위, 앱 데이터 복구, 장애 공지·배포 롤백을 실제 비민감 테스트 데이터로 연습 |
| 성능·유지보수 | 웹 빌드 성공. JavaScript 약 1.54MB(압축 약 389KB)로 경고 발생 | 공개 확대 전 코드 분할 검토. `pnpm` legacy 설정 경고와 Vite 7 peer 경고를 의존성 정리 과제로 등록 |

## 다음 승인 순서

1. 운영 책임자가 제한 파일럿의 참여자·기간·비민감 자료 범위·중단 기준을 서면으로 확정합니다.
2. 개인정보 처리방침, 이용약관, 외부 AI 전송/국외 이전 고지, 지원·삭제·침해 신고 URL을 실제 공개하고 법무 검토를 받습니다.
3. 웹에는 엣지 수준 속도 제한과 경보를, Windows·Android·iOS에는 각 플랫폼의 실제 설치·출력·잠금·오프라인 검증을 완료합니다.
4. Android는 내부/비공개 트랙과 Data safety·콘텐츠 등급을, iOS는 TestFlight와 App Store Connect 심사 자료를 각각 준비합니다.
5. 비민감 테스트 자료로 학생용 출력, 권한 분리, 데이터 삭제/복구, 장애 회수 절차를 리허설한 뒤에만 정식 공개 승인 회의를 진행합니다.
