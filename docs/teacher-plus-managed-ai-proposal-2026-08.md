# 교사 플러스 기능·관리형 AI 제공 제안

**작성일:** 2026-08-22  
**서비스:** EunmaStudio 교사도우미  
**상태:** 파일럿 의사결정용 제안 — 결제·자동 플랜 전환은 아직 구현하지 않음

## 1. 결론

**관리형 AI 사용량을 교사 플러스의 핵심 혜택으로 제공하는 방향은 타당합니다.** 다만 플러스의 본질은 ‘AI를 더 많이 쓰는 권한’이 아니라, 교사가 자료를 근거로 문항을 만들고 검수·출력하는 시간을 줄이는 **완성된 작업 흐름**이어야 합니다. 모델 API만 판매하면 원가 변동과 외부 모델 정책 변화에 직접 노출되고, 개인 API·로컬 모델 사용자에게는 효용이 작아집니다.

따라서 교사 기본은 서비스의 신뢰를 확인하고 실제 출제 보조를 할 수 있어야 하며, 교사 플러스는 **관리형 AI 월간 사용량 + 문제집 출력 + 작업 정리·복원·이관 편의성**을 묶는 구조를 권장합니다.

> 플랜은 출제 품질의 등급이 아니라 **교사의 시간을 아껴 주는 작업 도구의 범위**를 구분합니다. 자료 소유, 문항 검수, 개인 API·로컬 모델 사용권은 기본 플랜에서도 보장해야 합니다.

| 구분 | 교사 기본 | 교사 플러스 | 판단 근거 |
| --- | --- | --- | --- |
| 자료 등록·삭제·근거 확인 | 제공 | 제공 | 교사의 출제 책임과 자료 소유권에 필요한 핵심 기능 |
| 문항 생성·검수·수정 | 제공 | 제공 | 서비스의 기본 가치이므로 잠그지 않음 |
| 개인 API 키·Windows 로컬 모델·Android 온디바이스 모델 | 제공 | 제공 | 사용자가 비용·보안을 직접 선택하는 경로 |
| DOCX·기본 PDF·CSV 출력 | 제공 | 제공 | 데이터 이동성과 교사 작업물 반출 보장 |
| 문제집 조판 PDF·학생 정보란·교사용 해설 패키지 | 미제공 | 제공 | 인쇄 준비 시간을 줄이는 명확한 편의 기능 |
| EunmaStudio 관리형 AI | 파일럿 체험량 또는 미제공 | 월간 포함량 제공 | 비용이 발생하는 운영형 혜택 |
| 우선 처리·출력 템플릿·작업 꾸러미 이관 | 향후 일부 제공 | 단계적 제공 | 반복 작업을 줄이는 플러스 가치 |

## 2. 기존 기능 중 플러스로 옮길 후보

현재 제공되는 기능은 대부분 교사의 기본 출제 책임을 수행하기 위한 기능입니다. 따라서 자료 등록, 근거 확인, 문항 검수, 기본 문서 내보내기, 개인 API·로컬 모델은 플러스 전용으로 바꾸지 않는 것이 바람직합니다. 이미 구현한 **문제집 출력 패키지**는 표지·학생 정보란·교사용 해설 조판이라는 별도 편의가 있어 적합한 첫 플러스 기능입니다.

| 우선순위 | 플러스 후보 | 구현 상태 | 기본 플랜과의 경계 |
| --- | --- | --- | --- |
| P0 | 문제집 PDF·교사용 해설 PDF 조판 | 구현됨 | 기본 PDF·DOCX는 유지, 문제집 표지·학생 정보란·해설 조판만 플러스 |
| P1 | EunmaStudio 관리형 AI 월간 포함량 | 설계 필요 | 개인 API·로컬 모델은 계속 기본 제공 |
| P1 | 인쇄 템플릿 2~3종, 표지 문구·학교명 입력 | 설계 필요 | 내용 생성이 아니라 문서 편집 시간을 줄이는 편의 |
| P1 | 선택형 암호화 작업 꾸러미 이관 | 설계 완료, 구현 대기 | 기본은 단일 수동 내보내기, 플러스는 검증된 묶음·복원 안내 |
| P2 | 출력 이력, 재출력, 시험지 세트 버전 표기 | 설계 필요 | 문항 원본의 접근·삭제 권리는 모든 플랜에 유지 |
| P2 | 기관용 공유·승인 흐름 | 보류 | 개인 교사 파일럿과 별도 기관 플랜으로 분리 |

**옮기지 말아야 할 기능**은 자료 삭제·내보내기·개인 API·로컬 모델·문항 검수·근거 조회입니다. 이 기능들을 잠그면 교사가 자신의 자료와 결과물을 통제하지 못한다고 느끼거나, 보안상 로컬 경로를 고른 사용자를 불리하게 만들 수 있습니다.

## 3. 관리형 AI 제공 방식

현재 웹앱은 관리형 AI의 운영 규모를 확인하기 위해 날짜·작업·결과·모델·처리 시간 구간의 **익명 일별 합계**만 기록합니다. 사용자 ID·프롬프트·문항·파일명·IP는 집계에 포함하지 않습니다. 이 방식은 전체 운영 현황에는 적합하지만, 특정 계정의 월간 포함량을 제한하기에는 충분하지 않습니다.

교사 플러스에 관리형 AI를 포함하려면 다음의 별도 **사용량 권한 카운터**가 필요합니다.

| 항목 | 권장 설계 |
| --- | --- |
| 카운터 키 | 내부 사용자 식별자, 월, 작업 종류, 성공 여부 |
| 저장하지 않는 값 | 프롬프트·문항 원문·파일명·자료 본문·IP·대화 내용·개인 API 키 |
| 집계 단위 | ‘문항 생성 1회’, ‘자료 내용 추출 1회’처럼 교사가 이해할 수 있는 작업 단위 |
| 실패 처리 | 모델·네트워크 오류로 결과가 만들어지지 않으면 차감하지 않음 |
| 한도 처리 | 하드 차단보다 ‘이번 달 포함량을 사용했습니다. 개인 API/로컬 모델 또는 다음 달 포함량을 이용해 주세요’ 안내를 우선 표시 |
| 운영 화면 | 교사에게 남은 포함 작업 수와 다음 초기화 시점만 표시; 세부 프롬프트·문항은 표시·저장하지 않음 |

### 3.1 초기 파일럿 한도 제안

현재 가격·모델 비용이 확정되지 않았으므로, 아래 수치는 **출시 약속이 아닌 파일럿 측정값**으로만 사용해야 합니다. 실제 한도는 호출 1회당 입력 길이·자료 추출 여부·모델 원가·실패율을 2~4주간 익명 합계로 관찰한 뒤 확정합니다.

| 플랜 | 관리형 AI 제공 원칙 | 파일럿 표시 방식 |
| --- | --- | --- |
| 교사 기본 | 체험용 소량 또는 관리형 AI 미포함 중 하나를 선택 | ‘체험 사용량’으로 표시하고 개인 API·로컬 모델 경로를 항상 안내 |
| 교사 플러스 | 월간 포함 작업량 제공 | ‘이번 달 문항 생성 ○회 / 자료 내용 추출 ○회 남음’으로 표시 |
| 한도 소진 | 자동 과금 없음 | 개인 API·Windows 로컬·Android 온디바이스 전환, 또는 다음 초기화 시점 안내 |

자동 추가 과금, 초과 요금, 무제한이라는 표현은 **원가·정책·모델 공급 계약이 확정되기 전에는 사용하지 않는 것**이 안전합니다. 연 10,000원은 문제집 출력 중심의 파일럿 가격으로는 이해하기 쉬우나, 관리형 AI를 상시 포함하려면 실제 평균 원가를 확인한 뒤 가격 또는 포함량을 재검토해야 합니다.

## 4. 보안·동의 경계

관리형 AI는 웹 서버를 통해 외부 모델 또는 관리형 추론 경로로 요청을 처리할 수 있으므로, 로컬 모델과 같은 수준의 ‘기기 밖 전송 없음’을 약속해서는 안 됩니다. 관리형 AI 선택 시에는 작업별로 다음을 명확히 안내해야 합니다.

1. 문항 생성에는 선택한 자료의 발췌·교사 지시·생성 조건이 처리 경로로 전달될 수 있습니다.
2. 이미지·PDF 자료 내용 추출은 해당 파일 또는 필요한 페이지가 처리 경로로 전달될 수 있습니다.
3. 교사는 언제든 개인 API·Windows 로컬 모델·Android 온디바이스 모델로 전환할 수 있습니다.
4. 포함량 카운터에는 원문을 저장하지 않고, 작업 횟수·월·성공 여부만 최소 보관합니다.
5. 시험 예정 문항을 관리형 AI에 보내기 전에는 학교 보안 지침과 교사의 전송 동의를 다시 확인합니다.

## 5. 단계적 구현 권고

| 1단계 — 현재 | 교사 기본·교사 플러스 권한, 문제집 출력, 부드러운 플랜 안내 | 완료 |
| 2단계 | 월별 포함량 카운터, 남은 사용량 표시, 소진 시 개인 API·로컬 경로 안내 | 개인정보 처리방침·동의 문구와 플랜 정책 검토 완료 |
| 3단계 | 인쇄 템플릿, 표지·학교 정보, 암호화 작업 꾸러미 이관 | 출력 품질·복원 테스트 통과 |
| 4단계 | 실제 결제·구독 갱신·영수증·해지·환불 정책 | 결제 수단, 세무·소비자 고지, 고객 지원 체계 확정 |

## 6. 제안 결정

**지금은 교사 플러스에 관리형 AI를 ‘기능 예정’으로만 넣고, 즉시 포함량 판매는 시작하지 않는 것을 권고합니다.** 먼저 문제집 출력 패키지와 플랜 안내를 파일럿에서 검증하고, 다음 단계에서 관리형 AI의 사용자별 최소 카운터·동의·한도 화면을 구현한 뒤 실제 원가를 보아 포함량과 가격을 확정해야 합니다.

이 순서라면 교사는 개인 API·로컬 모델이라는 선택권을 잃지 않고, EunmaStudio는 비용 통제와 시험문제 보안의 설명 책임을 유지할 수 있습니다.
