# 개인정보 비수집 이용 통계 설계

> 이 문서는 운영 설계 초안이며, 정식 수집 전에는 실제 처리방침과 법률·개인정보 전문가 검토가 필요합니다.

## 원칙

사용자 식별·프로파일링이 아니라 **서비스 흐름이 유용한지**만 확인한다. 사용자 ID, 이메일, 이름, IP 주소, 기기 식별자, 쿠키 식별자, 원문 파일명, 자료 본문, 문항·프롬프트·정답, 개인 API 정보는 통계 이벤트에 저장하지 않는다.

## 수집 후보

| 목적 | 일 단위 집계 이벤트 | 저장하지 않는 값 |
|---|---|---|
| 시작 흐름 확인 | 자료 등록 완료 수, 기출 등록 완료 수 | 파일명·원문·사용자 ID |
| 생성 효용 확인 | 문항 생성 요청/성공/실패 수, 문항 수 구간 | 요구사항·근거·문항 본문 |
| 검수 효용 확인 | 승인·수정 승인·반려 수 | 검수자·검수 사유·문항 ID |
| UX 개선 | 화면별 오류 유형 수, PDF 원본 열기 수 | URL·페이지 원문·IP |
| AI 운영 | 제공자 유형별 성공/실패 수, 처리 시간 구간 | API 키·모델별 개인 식별 정보 |

## 수집 방식

이벤트는 발생 즉시 **날짜·이벤트 유형·정수 카운트만** 서버 집계표에 더한다. 개별 이벤트 행, 사용자 식별자, 정밀 시각, 요청 본문을 남기지 않는다. 일별 집계는 90일 보관 뒤 월별 합계로 축약하고, 운영자가 다운로드할 때도 집계표만 제공한다.

개인정보를 전혀 저장하지 않으면 ‘몇 명의 고유 교사가 사용했는지’는 정확히 알 수 없다. 대신 자료 등록→문항 생성→검수 완료의 **익명 흐름 건수**와 수정·반려 비율을 통해 파일럿의 실사용성을 판단한다. 이 방식이 현재 단계의 최소 수집 원칙에 더 적합하다.

## 도입 전 게이트

1. 운영 정책에 수집 목적, 집계 항목, 보존기간, 비수집 항목을 명시한다.
2. 통계 기능은 기본 비활성으로 배포하고, 운영자가 정책 문구를 확정한 뒤 활성화한다.
3. 집계 이벤트가 원문·식별자·IP·URL을 받지 않는 단위 테스트를 추가한다.
4. 기관 도입 시에는 계약과 기관 개인정보 기준에 맞춰 별도 검토한다.
