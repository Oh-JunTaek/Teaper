# Android 온디바이스 채팅 연속 대화 예산

## alpha.11 정책

E2B 채팅은 최대 컨텍스트를 **2,048 토큰**, 한 답변을 **128 토큰**으로 제한한다. 매 메시지마다 네이티브 `Conversation`을 새로 만들되, 앱 전용 저장소에 성공적으로 기록된 최근 **최대 4개 메시지**, 합계 **최대 600자**를 역할 정보와 함께 다시 전달한다. 즉 직전 사용자 질문·모델 답변과 현재 질문을 우선 보존하며, 새 대화·화면 재진입·네이티브 세션 재구성 뒤에도 동일한 범위의 문맥을 사용한다.

동기 `sendMessage()`가 내부 대화 이력을 유지하는지에 의존하지 않는 이유는 응답 후 네이티브 세션의 이력이 기기·런타임 상태에 따라 일관되지 않을 수 있기 때문이다. 저장 완료 이력을 다시 주입하면 모델이 직전 답변을 확인할 수 있고, 이전 alpha.10에서 유지한 짧은 CPU 안정성 실행 경로도 그대로 보존된다.

## 메모리 추정

KV 캐시의 근사식은 `2 × 레이어 수 × KV 헤드 수 × 헤드 차원 × 자료형 바이트 × 토큰 수`다. 16비트 캐시와 Gemma 계열에서 가능한 GQA 구조를 가정하면 2,048 토큰 KV 캐시는 약 **52~208 MiB**(1~4 KV 헤드 가정)이며, 8 KV 헤드의 보수적 상한 가정은 약 **544 MiB**다. 실제 앱은 여기에 2.58GB 모델 가중치, LiteRT-LM 네이티브 버퍼, Android 런타임과 화면 메모리를 더 사용한다.

현재 600자 최근 이력은 한국어·기호 비율에 따라 대략 300~700 토큰 범위이며, 시스템 지시문·자료 요약·교사 선호·현재 질문·128토큰 답변을 포함해 2,048토큰 제한 안에 머물도록 자료 요약 240자·교사 선호 120자로 별도 축약했다. 이 값은 S25+에서 4회 이상 후속 질문의 문맥 유지와 종료 재발 여부를 확인한 뒤 조정한다.
