# EunmaStudio 교사도우미 4플랫폼 기능·보안 점검 보고서

**작성일:** 2026-08-27
**대상:** 웹, Windows local-only, Android 온디바이스, iOS local-only 준비 기반
**판정 기준:** 교사가 자료를 준비하고 문항·쪽지시험을 생성해 직접 검수·보관·출력하는 공통 흐름과, 시험 자료가 교사 의도 없이 외부로 이동하지 않는 보안 경계입니다.

> **현황 결론:** 웹·Windows·Android는 일반 문항과 쪽지시험의 생성·문항별 검수·승인 보관·교사 확정 배점·학생용 출력이라는 핵심 흐름을 같은 의미로 제공합니다. iOS는 같은 쪽지시험·승인 보관·배점·학생용 PDF/공유의 **준비 기반**까지 구현됐지만, 자료 관리·메모·일정·일반 문항 생성·AI 채팅은 아직 포함하지 않았습니다. iOS를 세 플랫폼과 동등한 공개 서비스로 표현하거나 App Store에 제출해서는 안 됩니다.[1]

## 1. 이번 점검에서 즉시 보완한 항목

| 구분 | 확인 내용 | 조치 결과 |
|---|---|---|
| 대시보드 집계 | 일반 문항 수와 쪽지시험 문항별 상태가 분리되어, 검수 대기·승인 수가 실제보다 적게 보일 수 있었음 | 웹·Windows·Android의 대시보드/작업 현황에 쪽지시험 문항별 검수 대기·승인 수를 합산하고, 웹 검수함은 쪽지시험 검수 화면으로 이동하도록 연결 |
| 승인 보관함 | 개별 승인 쪽지시험 문항이 일반 승인 문항 보관함에 보이지 않았음 | 웹에서는 출처별 필터·검색·선택 내보내기로 통합. Windows·Android도 승인 쪽지시험 문항을 원래 검수 화면으로 이어지는 보관 동선에 표시 |
| 학생용 출력 | Android 일반 승인 문항 PDF/DOCX에 검수 상태·정답·해설이 섞일 위험이 있었음 | 학생용 문서 생성 직전에 정답·해설 구간과 검수 상태를 제거하고, 앱 전용 캐시와 일회성 공유 URI만 사용하도록 정리 |
| local-only 플랜 표시 | Windows의 플러스 워터마크 제거가 실행 환경 변수에 의존할 수 있었음 | 설치본 `package.json`의 기본 플랜 메타데이터만 읽도록 변경. 플러스는 서명된 배포본 메타데이터로만 지정하며, 판정 실패 시 기본 플랜으로 안전하게 처리 |
| iOS 로컬 파일 | iOS 준비 기반의 작업공간·모델 파일에 백업 제외·기기 잠금 보호가 부족했음 | 작업공간 JSON과 가져온 모델 파일에 `FileProtectionType.complete` 및 백업 제외 속성을 적용 |

자동 동기화는 기능 누락으로 보지 않습니다. 자료·문항·대화 원문이 다른 기기로 이동하려면 기본 비활성 동의, 암호화 키 소유와 복구, 범위 선택, 충돌·삭제·보존·사고 대응이 선행되어야 하므로 현 단계에서는 제공하지 않습니다.[2]

## 3. 보안 점검 결과

| 우선순위 | 항목 | 현재 상태 | 필요한 후속 조치 |
|---|---|---|---|
| **P0 완료** | 학생용 문서의 답·해설 노출 | 웹·Windows·Android·iOS 쪽지시험은 승인 문항만 사용. Android 일반 문항도 출력 직전 정답·해설·검수 상태를 제거 | 실제 PDF·DOCX·공유 앱에서 긴 문항과 여러 쪽 결과를 확인 |
| **P0 완료** | 기본/플러스 워터마크 우회 | 웹은 계정 플랜, local-only는 서명 배포 메타데이터로 판정. 런타임 환경 변수로 플러스를 지정하지 않음 | 출시 전 코드 서명과 플러스 배포 절차를 운영 문서로 확정 |
| **P0 완료** | iOS 자동 백업 노출 | 작업공간·가져온 모델 파일을 백업 제외하고 기기 잠금 이후 읽도록 보호 | iPhone 재부팅 뒤 잠금 해제·모델 준비·파일 복구 동작 검증 |
| **P1 보류** | Windows 원본 DB의 기기 분실 위험 | 사용자 전용 폴더 권한과 암호화 백업은 제공하지만, 실행 중 SQLite 본문 자체는 OS 파일 보호에 의존 | 학교 PC 계정 분리·OS 디스크 암호화 안내를 강화하고, 정식 공개 전 데이터베이스 암호화 도입 여부를 결정 |
| **P1 보류** | Android 저장소의 물리 접근 방어 | 자동 백업은 차단하고 앱 잠금은 제공하지만, 일반 기기 잠금 해제 뒤 앱 private 저장소는 OS 보호에 의존 | Android Keystore 기반 저장 암호화·사용자 통제형 암호화 백업 설계를 별도 검토 |
| **P1 보류** | iOS 앱 잠금 | 파일은 기기 잠금 보호이나 앱 내 생체/기기 인증 진입 UI는 아직 없음 | iOS 자료·문항·대화 화면에 선택형 앱 잠금과 재진입 잠금을 추가 |
| **P1 보류** | 외부 AI 전송 | 웹은 개인 API 선택 시 전송 동의. Windows·Android는 자동 외부 AI 전송 차단. iOS 모델 파일은 local-only | 웹에서 자료 발췌·문항 원문 전송 범위의 실제 파일럿 확인을 계속 수행 |
| **P2 보류** | 공유 뒤의 문서 통제 | 생성 전까지는 앱/서버 경계로 보호하지만, 교사가 공유한 PDF·DOCX·TXT는 대상 앱의 정책을 따름 | 공유 직전 보안 안내를 유지하고, 기관 도입 전 워터마크·암호화 문서·접근 로그 요구를 별도 검토 |

Windows Electron 창은 Node 통합을 끄고, 컨텍스트 격리·sandbox·웹 보안을 켜며, 외부 페이지 이동을 차단합니다.[3] Android는 자동 백업을 끄고 외부 저장소 권한 없이 FileProvider의 읽기 권한만 한시적으로 부여합니다.[4] 이 조치는 교사가 직접 공유한 이후의 수신자 접근 권한을 통제하는 기능은 아닙니다.
