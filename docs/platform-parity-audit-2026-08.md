# EunmaStudio 교사도우미 3플랫폼 기능·운영 점검 보고서

**작성일:** 2026-08-22  
**대상:** 웹앱, Windows 로컬 앱, Android 온디바이스 앱  
**판단 기준:** 교사가 자료를 준비하고, 문항을 생성·검수·보관·내보내는 공통 업무 흐름과 출시 예정 문항의 보안 경계

> **결론:** 세 플랫폼은 ‘자료를 준비해 교사가 검수할 문항을 만든다’는 핵심 방향은 공유하고 있습니다. 다만 웹은 **자료·근거·문서 출력**, Windows는 **local-only 생성·암호화 백업·문서 출력**, Android는 **온디바이스 모델·현장형 채팅·기기 잠금**에 강점이 분리되어 있습니다. 현재 가장 큰 공통 기능 차이는 **대화 기록/AI 채팅의 웹·Windows 미구현**, **Android의 문서형 내보내기와 상세 근거 확인 미구현**, **쪽지시험 내보내기 규칙의 미통일**입니다.

## 1. 점검 범위와 판정 방식

이 보고서는 정적 코드·문서·자동 테스트 상태를 기준으로 작성했습니다. 실제 기기에서만 확인할 수 있는 모델 발열, GPU 전환, APK 강제 종료 여부는 **‘실기기 확인 대기’**로 분리했습니다. 자동 동기화는 기능 누락이 아니라, 시험 자료 보안을 위해 명시적으로 보류한 **설계상 보안 경계**로 평가했습니다.[1]

| 상태 | 의미 |
|---|---|
| **공통 구현** | 세 플랫폼에서 같은 사용자 의미로 사용할 수 있음 |
| **의미는 공통, 수준 차이** | 기능은 있으나 근거·출력·관리 범위가 다름 |
| **플랫폼 전용으로 타당** | 하드웨어·OS·계정 특성상 공통화 대상이 아님 |
| **공통 보강 필요** | 교사의 핵심 업무 경험이 달라져 후속 반영이 필요함 |
| **실기기 확인 대기** | 코드·단위 테스트는 통과했으나 현장 확인이 남음 |

## 3. 확인된 핵심 격차

### 3.1 공통 반영 우선 격차

첫째, **교사용 AI 채팅과 대화 기록의 공통화 여부**가 가장 큰 제품 결정을 필요로 합니다. Android는 현장 질문·자료 확인을 위한 채팅, 제목 자동 제안, 즐겨찾기, 관리, 선택 공유를 갖췄지만 웹과 Windows는 동일한 교사 경험을 제공하지 않습니다. 채팅을 공통 업무 기능으로 유지할 경우 웹과 Windows에 같은 대화 데이터 계약, 공유 범위, 삭제, 프롬프트 비공개 정책을 구현해야 합니다. 반대로 Android 전용 현장 보조로 둘 경우, 공통 기능 계약 문서에 예외 사유를 명확히 기록해야 합니다.[1]

둘째, **Android의 문서형 내보내기와 근거 확인**이 부족합니다. 웹과 Windows는 교사가 검수한 문항을 DOCX/PDF/CSV로 문서화하는 흐름이 있지만 Android는 현장 생성·공유 중심입니다. 최소한 승인 문항의 PDF 또는 DOCX 생성, 근거 자료 파일명·페이지·발췌 확인, 원본 파일 열기까지는 공통 업무 결과물로 맞추는 편이 바람직합니다.

셋째, **쪽지시험의 출력·이동성**이 다릅니다. Windows에는 승인 쪽지시험 TXT 내보내기가 있지만 웹·Android에는 동등한 흐름이 없습니다. 쪽지시험을 수업 직전 활용하려면 ‘승인한 세트의 인쇄용 PDF’, ‘교사용 답안 포함/제외 텍스트’, ‘다른 플랫폼으로 옮기지 않는 로컬 저장’ 중 어디까지가 공통 기본인지 확정해야 합니다.

### 3.2 운영 전 출시 전 격차

가장 중요한 운영 격차는 **삭제·보존·복구 정책의 플랫폼별 불균형**입니다. Windows는 암호화 백업·복구를 제공하지만 Android에는 사용자가 통제하는 암호화 백업이 없고, 웹은 계정 데이터 삭제·보존 기간·지원 문의 흐름을 실제 운영 조건에 맞게 확정해야 합니다. 이는 기능 편의보다 시험 자료 보안과 교사 신뢰에 직접 연결됩니다.

또한 공식 교육과정·기출 자료는 단순 링크 제공을 넘어, **공식 원문 변경 감지 → 운영자 검토 → 교사에게 변경 사실 고지 → 기존 문항 근거와의 버전 연결** 흐름이 필요합니다. 자동 수집·무검토 반영은 자료 권리·정확성 위험이 있어 권장하지 않습니다.

## 5. 이번 점검의 권고 결정

지금은 기능을 넓히기보다 **Android 안정성 검증을 먼저 끝내고, ‘문서 출력·근거 확인·쪽지시험 내보내기’를 다음 공통 기능 묶음으로 확정**하는 것이 좋습니다. 이 세 항목은 웹·Windows의 강점을 Android에 이식하는 작업이며, 서비스의 본질인 ‘교사가 근거를 확인해 결과물을 검수하고 수업에 사용한다’는 흐름을 가장 직접적으로 완성합니다.

AI 채팅은 Android에서 사용성이 확인되고 있으므로, 다음 제품 결정 회의에서 **(A) 세 플랫폼 공통 기능으로 확장**하거나 **(B) Android 현장형 보조 기능으로 명시적 예외 처리** 중 하나를 선택하는 것을 권고합니다. 현 시점에서는 원문 대화를 자동 동기화하지 않는 현재 보안 경계를 유지해야 합니다.[1]
