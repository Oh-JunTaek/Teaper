# 하이브리드 AI 출제 보조 서비스 출시 점검

## 검토 범위와 결론

이 문서는 화학 I 파일럿을 실제 서비스로 운영하기 전 필요한 **개인정보·문항 보안·외부 AI 전송·모델 라이선스·저작권** 운영 통제를 정리한 내부 점검 기준이다. 법률 자문 자체를 대체하지 않으며, 유료 전환·학교 단위 도입·미성년 학생 정보가 포함될 수 있는 사용 사례로 확대하기 전에는 개인정보·교육·저작권 전문 자문을 받아야 한다.

개인정보보호위원회는 생성형 AI의 서비스형 LLM, 오픈소스 LLM, 자체 개발 방식을 구분하여 생애주기별 안전조치와 CPO 중심 거버넌스를 제시하고 있다. [1] 또한 국외 사업자가 개인 정보를 조회하는 경우에도 국외이전에 해당할 수 있고, 별도 동의·계약 이행을 위한 처리위탁 등 적법 근거 및 안전조치가 요구될 수 있다. [2]

| 출시 구분 | 현재 상태 | 출시 판단 |
|---|---|---|
| 개인 교사 비상업 파일럿 | 사용자별 제공자 설정, 요청별 외부 전송 동의, 문항·근거 이력, 교사별 문항 격리 적용 | 제한적 운영 가능. 안내·삭제 요청·침해 대응 체계를 먼저 공개 |
| 외부 개인 API 사용 | 전송 범위 미리보기, 요청별 동의 시각 기록, API 키 암호화 | 제공자별 처리방침·국가·보관 정책 확인 후 허용 |
| 로컬 전용 데스크톱 | 공통 데이터 계약 및 암호화 vault 구현, 실제 브리지·배포 패키지는 미완료 | 웹 배포와 분리된 데스크톱 단계에서만 출시 |
| 학교·교육청 기관 도입 | 기관 계약·관리자·보존기간·감사 로그 정책 미완료 | 별도 보안성 검토와 계약 체결 전에는 제공 금지 |

## 개인정보 및 외부 전송 통제

서비스는 문항 원문, 교사의 추가 요구사항, 교사 업로드 자료에 학생 이름·평가 정보·학교 내부 정보가 섞일 수 있음을 전제로 한다. 따라서 외부 API 사용 시에는 필요한 최소 범위를 사전에 표시하고, **이번 요청에 한정된 명시 동의**가 있어야 호출되도록 구현했다. 동의 기록은 생성 요청에 제공자 유형·모델·시각과 함께 저장되어 검수 화면에서 확인할 수 있다.

| 통제 항목 | 운영 기준 | 구현 상태 |
|---|---|---|
| 데이터 최소화 | 외부 전송 전 출제 조건, 선택 근거 건수, 추가 요구사항 전문 여부를 표시하고 불필요한 식별정보 입력을 금지 | 구현 |
| 요청별 동의 | 개인 Gemini/OpenAI 호환 API는 요청별 체크 없이는 생성 차단 | 구현 |
| 국외이전 고지 | 처리방침에 제공자, 이전 국가·시점·항목·목적·보유·이용자 권리 행사 방법을 서비스 구성에 맞게 기재 | 출시 전 필수 |
| 비밀정보 보호 | API 키는 웹에서는 AES-256-GCM 암호화, 로컬 모드에서는 암호화 vault에 분리 보관 | 구현 |
| 보존·파기 | 문항·자료·생성 이력·접속/감사 로그별 보존기간과 파기 방식을 정책화 | 출시 전 필수 |
| 권리 요청·사고 대응 | 열람·정정·삭제·전송 중지 요청 경로, 침해 통지·조사 절차와 담당자 지정 | 출시 전 필수 |

> 국외이전 시에는 처리방침 공개, 안전성 확보조치, 침해에 대한 고충처리·분쟁 해결 조치가 요구될 수 있다. 서비스의 실제 전송 구조와 계약관계에 맞춘 법률 검토가 필요하다. [2]

## 출시 예정 문항 보안

출시 예정 시험문항은 일반 참고자료보다 높은 보안 등급으로 취급한다. 교사는 자신이 만든 문항만 목록·상세·CSV 내보내기·검수 대상에서 볼 수 있고, 관리자는 운영 목적의 전체 열람 권한을 가진다. 이 접근 통제는 서버 절차에서 적용해야 하며, 화면 숨김만으로 구현하면 안 된다.

| 위험 | 필수 대응 |
|---|---|
| 다른 교사 문항 열람 | 서버 기준 생성자 소유권 검사, 관리자 역할의 최소 인원화, 정기 권한 검토 |
| 외부 AI에 원문 전송 | 기본적으로 로컬/관리형 선택을 안내하고, 외부 제공자는 요청별 명시 동의와 전송 범위 확인 뒤에만 허용 |
| 개인 키 노출 | 화면·로그·내보내기에 키를 넣지 않고, 마스킹과 암호화 저장을 유지 |
| 계정 탈취 | 운영 전 MFA/강한 인증 수단, 세션 만료, 관리자 접근 기록, 비정상 로그인 알림 검토 |
| 운영자 과다 권한 | 운영자 문항 열람 목적·절차를 문서화하고, 기관 도입 시 감사 로그와 승인 절차 추가 |

개인정보보호위원회의 안전성 확보조치 기준 안내서는 개인정보처리자가 충족해야 할 최소 보호 기준을 다루므로, 운영 전 접근권한·암호화·접속기록·백업·사고대응 항목을 해당 안내서에 비추어 점검해야 한다. [3]

## 저작권·모델 라이선스·교육 자료

기출문제 및 교재 원문은 단순히 비상업적 목적이라는 이유만으로 재배포·학습·복제가 자동 허용되지 않는다. 현 서비스의 원칙은 **공식 링크와 메타데이터 우선**, 본문 RAG 사용은 명시적 권리 검토 또는 이용 허락이 있는 자료에 한정, 문항 생성 결과는 검수 전 시험지로 사용하지 않음이다.

| 자산 | 운영 원칙 | 출시 전 증빙 |
|---|---|---|
| 교육부·NCIC 문서 | 출처 URL·공표일·적용연도·권리 상태 기록, 변경 감지 후 관리자 승인 | 이용 조건과 원문 활용 범위 |
| KICE·국가 기출 | 공식 링크·메타데이터 중심, 원문 복제·재배포 금지 | 저작권자 또는 제공처 이용 조건 |
| 교사 업로드 자료 | 업로드자가 이용 권한을 보유했음을 확인, 공유 범위 선택 | 이용자 약관 및 업로드 확인 절차 |
| Ollama/오픈 모델 | 모델 가중치·상용 이용·재배포·파생물 조건을 모델별로 확인 | 모델 카드·라이선스 사본·버전 기록 |
| 외부 AI API | 입력의 학습 사용 여부, 보존기간, 국외 전송, 비용·한도 정책 확인 | 제공자별 최신 약관·처리방침 승인 기록 |

## 운영 승인 게이트

아래 항목을 모두 충족하기 전에는 ‘정식 서비스’ 또는 기관 판매로 전환하지 않는다. 개인 교사 파일럿은 고위험 정보 입력 금지와 수동 검수 원칙을 첫 화면 및 약관에 분명히 고지한다.

1. 개인정보 처리방침, 이용약관, 문항 보안 안내, 업로드 권리 확인 문구를 공개한다.
2. `PERSONAL_API_ENCRYPTION_KEY`를 무작위 운영 키로 교체하고 키 교체·복구 절차를 기록한다.
3. 관리자 계정을 최소화하고 관리자 행위·문항 열람을 감사 가능한 방식으로 기록한다.
4. 자료·문항·생성 이력의 보존기간 및 삭제·내보내기 절차를 제품에 구현한다.
5. 제공자별 API 약관, 모델 라이선스, 국외이전 고지 내용을 최신 상태로 검토한다.
6. 실제 로컬 전용 제품은 데스크톱 브리지의 loopback 제한·OS 보안 저장소·모델 설치 검증·업데이트 서명을 별도 검증한다.
7. 기관 도입 시 개인정보 처리위탁/국외이전 계약과 기관의 보안 정책을 개별 검토한다.
