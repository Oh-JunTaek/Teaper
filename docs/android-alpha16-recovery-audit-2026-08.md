# Android alpha.16 복구 감사 기록

## 확인된 불일치

alpha.15는 `versionCode=15`, `versionName=0.1.0-alpha.15`로 패키징되었지만, 실제 채팅 실행 경로에는 이전 구현이 남아 있었다. 이전 구현은 `sendMessageAsync(..., 384)` 스트리밍 콜백을 UI 갱신과 함께 사용했고, `SharedPreferences.apply()`로 대화 저장을 비동기로 처리했다. 이 경로에는 대화 컨텍스트 상한, 동기 저장 확인, 프롬프트 추출 차단, Markdown 렌더링 정책 파일이 없었다.

따라서 사용자가 alpha.15에서 이전 상태 안내·응답 후 종료·일반 텍스트 표시를 본 것은 재현 가능한 산출물 불일치였다. 홈 A+C 시각 변경은 있었지만, 채팅·저장·정책 소스가 이전 상태로 되돌아간 채 APK가 조립된 것이 원인이다.

## alpha.16 복구 범위

alpha.16은 채팅을 CPU 안정성 모드의 2,048토큰 엔진으로 초기화하고, 최근 4개 메시지·600자만 역할 이력으로 전달한다. 요청마다 새 `Conversation`을 만들고 **동기 `sendMessage()`**로 응답을 완성한 뒤 즉시 닫는다. 사용자 메시지 저장 확인 → 모델 응답 → 모델 메시지 저장 확인 → Markdown 렌더링 순서를 사용한다.

프롬프트·시스템 메시지의 직접·간접 추출 요청은 모델 호출 전에 고정 안전 안내로 처리한다. 제목·목록·굵은 글씨·인라인 코드는 Android Span으로만 표시하며 HTML·스크립트·자동 URL 실행은 하지 않는다. 단위 테스트와 Debug APK 조립을 통과했고 설치 APK의 SHA-256은 `6f182d28260729810d40d9bb3c5d72fadbd848436522b96d7702fa75a0e16bb3`이다.
