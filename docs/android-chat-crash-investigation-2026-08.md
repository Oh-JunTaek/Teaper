# Android 온디바이스 채팅 종료 조사 기록

## 2026-08-22 — alpha.10 후보

S25+에서 모델 답변이 잠시 보인 뒤 앱이 종료되고 답변이 대화 기록에 남지 않는 현상을 분석했다. Android 앱의 채팅 흐름은 사용자 메시지의 동기 저장 확인, 모델 준비, LiteRT-LM 동기 응답 수신, 모델 메시지의 동기 저장 확인, 화면 확정 순서다. 따라서 모델 메시지가 남지 않는 것은 저장 기능 자체의 실패만을 의미하지 않으며, 모델 호출이 반환되기 전에 네이티브 프로세스가 끝날 경우에는 저장 단계에 도달하지 못해 발생할 수 있다.

현재 SharedPreferences의 채팅 스레드 쓰기는 비동기 `apply()`가 아닌 성공 여부를 반환하는 동기 `commit()`을 사용한다. 모델 응답은 저장 성공 이후에만 최종 답변으로 화면에 확정하며, 저장 또는 렌더링 관련 Kotlin 예외는 같은 화면에서 재시도 가능한 안내로 처리한다. 다만 네이티브 코드의 프로세스 종료는 Kotlin `try/catch`로 복구할 수 없으므로 실기기 로그가 필요하다.

LiteRT-LM 0.16.1 `EngineConfig`에는 `maxNumTokens`를 설정할 수 있다. 채팅은 CPU 안정성 모드에서 128개의 출력 토큰과 2,048개의 최대 컨텍스트 토큰을 사용하도록 분리했다. 이 값은 기본 문항 생성 경로의 4,096 토큰과 분리되어 KV 캐시 할당량을 낮추기 위한 조치다. 다음 실기기 검증에서는 짧은 질문, 자료 사용 설정 해제, 새 대화에서 응답 완료·앱 재시작 후 보존 여부를 순서대로 확인한다. 종료가 재현되면 Android `logcat` 또는 시스템 오류 보고서의 네이티브 크래시·저메모리 흔적을 확보해야 한다.
