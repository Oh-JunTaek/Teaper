## 1. 현재 판단

서비스는 교사가 근거를 확인하면서 문항을 만들고 검수하는 **화학 I 출제 보조 파일럿**으로 사용할 수 있는 기반을 갖췄다. 핵심 가치는 단순 문항 생성이 아니라, 교육과정·교사 자료·기출 유형·출제 지침을 문항과 연결하고 검수 기록을 남기는 데 있다.

개인 교사 파일럿 단계에서는 사용자 목록·역할 변경 기능의 효용이 낮고 개인정보 노출 면적만 늘어난다. 따라서 해당 UI는 비노출로 보류하고, 향후 기관 도입 시 관리자 책임자·계약·감사 절차와 함께 재활성화하는 것이 적절하다. 공식 출처·정책 관리 등 서비스 운영 기능은 운영 도구로 유지한다.

| 영역 | 현재 상태 | 파일럿 판단 |
|---|---|---|
| 참고 자료 | PDF·이미지·웹 링크 등록, 텍스트 추출, 삭제, 원본 위치 기록 | 사용 가능 |
| 기출문제 | 개인 작업공간 등록, 출처·문항 번호·페이지·원본 PDF 연결 | 사용 가능 |
| 문항 생성 | 근거 검색, AI 제공자 선택, 생성·검증·근거 스냅샷 | 사용 가능, 교사 검수 필수 |
| 그래프·표 | SVG 그래프·표 자료 생성·검수 표시 | 사용 가능, 과학적 정확성 검수 필수 |
| 검수·내보내기 | 승인·수정·반려 이력, 승인 문항 CSV | 사용 가능 |
| 개인정보 보호 | 교사별 자료·문항 격리, 사용자 관리 비노출, API 키 암호화 | 지속 점검 필요 |
| 로컬 AI | vault·SQLite·bridge 기반 구현 | 설치형 UI·배포 패키지 전 |

## 2. 개인정보 비수집 이용 통계 판단

파일럿에서 필요한 것은 누가 무엇을 했는지 추적하는 것이 아니라, **어느 흐름이 실제로 도움이 되는지** 확인하는 것이다. 따라서 아직 개인 단위 분석을 도입하지 않고, 익명 일별 집계만 수집하는 방식을 권장한다.

수집 후보는 자료 등록 완료 수, 기출 등록 완료 수, 문항 생성 요청·성공·실패 수, 승인·수정 승인·반려 수, PDF 원본 열기 수, 제공자 유형별 성공·실패 수와 처리 시간 구간이다. 사용자 ID, 이메일, IP, 쿠키 식별자, 파일명, 문항·자료 원문, 프롬프트, 정답, 검수 사유, API 키는 수집하지 않는다.

현재는 통계를 **설계만 완료**하고 실제 수집은 비활성으로 둔다. 운영 정책에 목적·항목·보존기간·비수집 항목을 명시하고, 법률·개인정보 검토를 마친 뒤 일별 집계 테이블로 도입한다. 고유 사용자 수처럼 식별자가 필요한 지표는 수집하지 않는 대신, 익명 흐름 건수와 검수 결과 비율로 사용성을 판단한다.

## 3. 파일럿에서 검증할 질문

| 검증 질문 | 확인 방법 | 성공 신호 |
|---|---|---|
| 자료 등록이 부담스럽지 않은가 | 교사 3~5명의 첫 사용 관찰 | 자료 또는 기출 등록 후 첫 생성까지 막힘이 적음 |
| 근거가 납득 가능한가 | 검수 화면에서 원본·페이지 대조 | 사용자가 출처와 위치를 빠르게 확인 |
| 문항 생성이 시간을 줄이는가 | 생성 전후 수작업 시간을 교사 스스로 기록 | 초안 작성보다 검수·수정에 집중 |
| 그래프·표가 활용 가능한가 | 그래프 축·단위·곡선 검수 | 설명문 대체가 아닌 실제 자료로 사용 |
| AI 설정이 어려운가 | 관리형 AI 기본 사용 성공률, 설정 문의 | 개인 API 없이도 기본 흐름 완주 |
| 보안 안내가 명확한가 | 외부 AI 전송 미리보기 이해 여부 | 전송 범위와 로컬 선택의 차이를 이해 |

## 4. 다음 우선순위

### P0 — 파일럿 전 필수

1. 운영 암호화 키를 무작위 운영 키로 교체하고 복구 절차를 기록한다.
2. 개인정보 처리방침·이용약관·자료 권리 확인·보존/삭제 정책의 실제 운영 문구를 확정한다.
3. 3~5명 교사와 실제 화학 I 단원으로 파일럿을 진행하고 오류·수정 시간·근거 만족도를 기록한다.

### P1 — 파일럿 사용성 개선

1. PDF에서 페이지·문항 번호를 자동 추출하는 보조 기능을 추가한다.
2. 그래프 축·단위·좌표를 검수 화면에서 직접 수정하게 한다.
3. 비개발자용 AI 연결 마법사를 구현하고 관리형 AI를 기본 경로로 강화한다.
4. 승인 문항을 그래프·표와 함께 PDF 또는 편집 가능한 시험지 형식으로 내보낸다.

### P2 — 기관 도입 준비

1. 기관 관리자, 교사, 검토자 역할과 승인·감사 이력을 설계한다.
2. 기관별 자료 분리, 보존기간, 삭제 요청, 접근 기록을 구현한다.
3. 비노출 상태의 사용자 관리 기능을 기관 정책에 맞춰 재활성화한다.

## 5. 기술·품질 현황

현재 TypeScript 검사를 통과하고 **44개 단위 테스트**가 통과했다. 테스트는 권한, 참고 자료, 공식 카탈로그, AI 제공자, 개인 키 암호화, 근거 선택·스냅샷, 그래프 자료, 저장 키, 공통 프롬프트 계약을 포함한다. 다만 실제 교사 파일럿의 문항 품질과 사용성은 자동 테스트만으로 판단할 수 없으므로, 다음 단계의 핵심은 제한된 현장 사용 검증이다.
